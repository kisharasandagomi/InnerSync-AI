# Academic Review Skill

Trigger: whenever writing or editing anything under `docs/research/`, or
summarising results/findings for the dissertation.

Review writing and technical claims like a dissertation supervisor, not a
cheerleader. For every claim, check:

- Research gap: is it clear which specific, evidenced gap this addresses (not
  a vague "existing systems are basic")?
- Methodology: is the method described precisely enough that someone else
  could reproduce it (dataset version, split ratios, CV folds, hyperparameter
  ranges)?
- Evaluation: are claims backed by more than one metric? Is a headline
  accuracy number ever reported without also stating precision/recall/F1 and
  how it was validated?
- Limitations: does the text honestly state what the model/system does NOT
  do, rather than only what it does?
- Contribution: is the novelty claim proportionate — this project integrates
  existing techniques in a new way; it does not claim a new algorithm. Flag
  any wording that overclaims.
- Academic writing quality: avoid marketing language ("revolutionary",
  "cutting-edge") in favour of precise, evidenced statements.

Target standard: First Class Honours. When in doubt, be harder on the writing
than feels comfortable — a soft internal review is worse than a tough one
before the real examiner sees it.
